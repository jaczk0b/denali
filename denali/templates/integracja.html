{% if cls.type == "proxmox" %}

Jedno konto do wszystkiego

Panel używa jednego konta denali@pve z jednym tokenem. Zaznaczasz, co ma móc, a polecenie nadaje dokładnie tyle. Akcje i konsola dotyczą tylko maszyn (/vms), bez dostępu do ustawień węzła.

Adresy IP maszyn wirtualnych wymagają agenta QEMU w VM (qemu-guest-agent); bez niego VM pojawi się bez IP.

{% elif cls.type == "komodo" %}

Jak założyć klucz (tylko odczyt)

  1. W Komodo: Settings → Users — dodaj użytkownika usługowego, np. denali, bez uprawnień administratora.
  2. Daj mu prawo Read do serwerów i stacków (bez Execute i Write).
  3. Na tym użytkowniku: API Keys → New. Skopiuj Key i Secret — Secret widać tylko raz.

Klucz do akcji (opcjonalnie)

  1. Drugi użytkownik usługowy, np. denali-akcje, bez uprawnień administratora.
  2. Na stackach, którymi panel ma sterować: Permissions → Execute dla tego użytkownika (nie Write).
  3. Na nim API Keys → New — Key i Secret wpisz w sekcji „Akcje” na tej stronie.

Adres to adres panelu Komodo (Core), nie periphery na serwerach. Serwery Komodo pojawią się w kolejce z adresem IP — „Przypnij dopasowane” połączy je z VM-kami z Proxmoxa, a stacki trafią pod swoje VM-ki.

{% elif cls.type == "pbs" %}

Jak założyć token (tylko odczyt)

  1. W PBS: Configuration → Access Control → User Management → Add: użytkownik denali, realm pbs.
  2. API Token → Add: użytkownik denali@pbs, Token Name odczyt. Skopiuj Secret — widać go tylko raz.
  3. Permissions → Add → API Token Permission: ścieżka /, token denali@pbs!odczyt, rola Audit, Propagate zaznaczone.
  4. Certyfikat: Administration → Shell → cat /etc/proxmox-backup/proxy.pem, skopiuj całość.

Kopie podepną się same pod karty VM i kontenerów z Proxmoxa (po numerze VM). Serwer PBS pojawi się w kolejce — „Przypnij dopasowane” połączy go z jego VM.

{% elif cls.type == "truenas" %}

Jak założyć klucz API

  1. W TrueNAS: Credentials → Local Users → Add: użytkownik denali, bez hasła logowania, bez powłoki.
  2. W nowszych wersjach: Credentials → Groups — dodaj go do grupy z rolą READONLY_ADMIN.
  3. Klucz: ikona użytkownika (prawy górny róg) → API Keys → Add dla denali. Skopiuj klucz — widać go tylko raz.
  4. Certyfikat: Credentials → Certificates → truenas_default → pobierz i wklej zawartość (albo wyłącz sprawdzanie).

Starsze wersje TrueNAS nie mają ról tylko do odczytu — wtedy klucz ma pełne prawa, a Denali i tak tylko czyta. Pule, snapshoty i replikacje pojawią się na karcie TrueNAS.

{% elif cls.type == "tplink" %}

Router TP-Link — przeczytaj przed dodaniem

  • To nieoficjalne połączenie (biblioteka tplinkrouterc6u). TP-Link nie ma kont tylko do odczytu, więc potrzebne jest hasło administratora routera — Denali trzyma je zaszyfrowane i tylko czyta.
  • Przy odczycie Denali loguje się jako administrator i od razu się wylogowuje. Jeśli w tym momencie masz otwarty panel routera w przeglądarce, może Cię wylogować — dlatego odczyt jest co 5 minut.
  • Po aktualizacji firmware'u TP-Linka połączenie może przestać działać — integracja pokaże błąd, a ping routera działa dalej.
  • Drugi router działający jako AP dodaj osobno i zaznacz „punkt dostępowy”.

Podłączone urządzenia trafią do „Do zatwierdzenia” (nowe urządzenie w sieci). Znane dopasują się po MAC. Telefony i laptopy dostają profil „Komputery i telefony” — bez pingu i powiadomień.

{% elif cls.type == "ovh" %}

Jak założyć klucze OVH

  1. Otwórz formularz tokenu OVH ↗ — uprawnienia są już wpisane (same odczyty). Region CA i US ma ten formularz pod własnym adresem API.
  2. Zaloguj się kontem OVH, nazwij aplikację denali, ważność ustaw na Unlimited.
  3. Skopiuj tutaj Application Key, Application Secret i Consumer Key. Sekret widać tylko raz.

VPS-y trafią do „Do zatwierdzenia”. Po zatwierdzeniu VPS ma terminal SSH i zwykłe sprawdzenia z adresu. Bez uprawnień do /me zakładka VPS działa dalej, tylko bez zaległości i faktur. Public Cloud nie jest obsługiwany.
